# GF-002 重铸结果可以通过反复放取免费刷新

- 优先级：P1
- 状态：待决议（Q4）
- 相关：ADR-0001、GF-001

## 问题

重铸在 `assemble` 里用 `RandomSource.create()`（`GearSmithingRecipe.java:127`）生成新词条。锻造台在放入物品时就计算并显示结果，取出前不消耗任何东西。玩家把重铸石拿出来再放回去，结果格就换一组词条，可以无限刷到满意为止，一块重铸石等于“任选词条”。

2026-11 整理时尝试过“用装备当前状态做种子”，但这样所有全新的同种装备会重铸出完全相同的词条，已撤回。

## 修复方案

**方案 A：每个玩家一个重铸种子（推荐）**

仿照原版附魔台的 `enchantmentSeed`：

1. 给玩家加一个数据附件 `reroll_seed`（`AttachmentType`，随玩家存档）。
2. Mixin `SmithingMenu.createResult` 在调用配方前把当前玩家放进一个 `ThreadLocal`（`ItemCombinerMenu` 有 `player` 字段），`assemble` 读取后用 `种子 ^ 装备状态哈希` 建随机源。
3. `SmithingMenuMixin.onTake` 在重铸成功后把玩家种子换成新随机值。

效果：预览就是实际结果；放取多少次都不变；每次真正重铸后才变化；不同玩家、不同装备结果不同。

**方案 B：取出时才掷骰**

预览显示“词条：???”，`onTake` 时生成。实现简单，但快速取出路径里 `onTake` 拿到的已是移入背包后的空栈，需要额外处理；玩家看不到结果预览。

**方案 C：保留现状，当作玩法**

在提示文本里写明“可预览重铸结果”，并考虑提高重铸石成本。

## 验收标准（方案 A）

- 同一玩家、同一装备，反复放取重铸石，预览词条不变。
- 取出后再放一块重铸石，预览变化。
- 两个玩家对同样的全新装备重铸，结果不同。
- 服务器重启后种子保留。
