# GF-007 配置不从服务端同步到客户端

- 优先级：P1（只影响多人游戏）
- 状态：已修复（ADR-0007）：新增 `gear_forge:config_sync` payload，服务端在登录时下发快照，客户端只覆盖内存。
- 相关：ADR-0002、ADR-0003

## 问题

`ModConfigs` 在客户端和服务端各自读本机的 `config/gear_forge/*.json`。服务端改过平衡数值后，连进来的玩家：

- 物品提示里的词条名称、数值格式、宝石效果按客户端自己的配置显示（`GearEventHandlers.java:742`、`:918` 等）。
- 锻造台预览由客户端先算一遍，再被服务端结果覆盖，强化上限、插槽数不同时预览会闪一下或显示错误。
- 服务端新增的词条 id 在客户端查不到，提示里显示原始 id。

实际伤害、属性由服务端计算，不受影响。

## 修复方案

**方案 A：登录时同步（推荐）**

1. 注册一个 `CustomPacketPayload`，内容是四份配置的 JSON 字符串（或压缩后的字节）。
2. `PlayerEvent.PlayerLoggedInEvent` 和配置重载时由服务端发给客户端。
3. 客户端收到后覆盖内存里的 `ModConfigs`（不写回本地文件），断开连接时恢复本地配置。
4. 单人游戏（集成服务端）共享同一份内存，无需特殊处理。

**方案 B：改成数据包注册表**

把词条定义、宝石定义改成 `DataPackRegistryEvent.NewRegistry` 注册的同步注册表（`data/<命名空间>/gear_forge/affix/*.json`）。原版负责同步和按世界生效，整合包作者可以用数据包改。改动大，需要重写 ADR-0003，现有玩家的 `config/gear_forge` 修改需要迁移。

## 验收标准

服务端把某词条显示名和数值范围改掉后，客户端连入，提示文本显示服务端的名称；断开后进单人世界恢复本地配置。
