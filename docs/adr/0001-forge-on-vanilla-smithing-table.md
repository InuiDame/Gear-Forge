# 所有锻造操作通过一个自定义锻造配方在原版锻造台上完成

模组没有自己的工作方块和界面。八种锻造操作都由 `GearSmithingRecipe`（类型为原版 `RecipeType.SMITHING`）实现，按第三格材料分派。这样不用写方块、方块实体、菜单和网络同步，玩家也不用学新的工作台；代价是必须接受原版锻造台的行为。

## Consequences

- 原版取出产物时三个输入格各扣 1 个。`assemble` 只能产出 1 个；需要多个材料的操作必须用 mixin 补扣（`SmithingMenuMixin`，目前只有转生）。以后如果强化要按等级消耗多颗钻石，也走这条路。
- 结果在取出前就会显示。任何带随机性的操作（重铸、以后可能的强化成功率）都要专门处理“预览”和“实际结果”的关系（GF-002、GF-001）。
- 配方 `matches` 也会在客户端执行，用的是客户端本地配置（GF-007）。
- JEI/EMI 之类的配方查看器看不到这些操作，因为配方没有固定的输入输出。

## Considered Options

- 自定义锻造台方块和界面：可以自由控制消耗、随机和展示，但工作量大得多。如果 GF-001/GF-002 的需求继续增加，值得重新评估。
- 右键使用材料（材料物品的 `use`）：语言文件里残留 `message.gear_forge.no_gear`（“请在另一只手拿着装备”）、`need_diamonds` 等文案，看起来早期版本用过这种方式，后来改成锻造台。
