# 一项数值只走一条生效路径：原版属性能表达的挂属性修饰符，其余走事件

原版有对应属性的数值（攻击、攻速、护甲、韧性、移速、生命、击退、幸运）通过 `ItemAttributeModifierEvent` 挂到物品上，其余效果（暴击、元素伤害、宝石固定减伤、闪避、荆棘等）在伤害和 tick 事件里结算。同一项数值不能两边都加。2026-11 整理前，强化攻击/护甲/韧性和部分转生保留奖励既挂了属性又在伤害事件里再加一遍，实际效果是提示文本的两倍。

修饰符 id 必须带槽位后缀（`gear_forge:<名字>/<槽位>`）。原版按 id 合并修饰符，几件盔甲用同一个 id 时只有一件生效，脱下其中一件还会把其它件的同 id 修饰符一起移除。盔甲的修饰符只挂在它自己的护甲槽，不在手持时生效。

状态为 proposed：去掉重复计算等于把强化的实际收益减半，需要作者确认（grill 问题 Q1、Q2）。

## Consequences

- 强化、转生后的攻击和护甲收益与提示文本一致，但比 1.6.51 之前的实际数值低。
- 以后新增数值时，先判断原版有没有对应属性，再决定放哪条路径。
